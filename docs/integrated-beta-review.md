## 원인과 변경

1. `planLocalReplacement`가 모든 사각형 교차를 동일하게 거절했다. AI가 카드와 그 안의 글자를 함께 찾으면 두 후보 모두 탈락했다. 수정은 더 낮은 zIndex의 도형이 **여유 경계까지 포함하는 경우**에만 자식 추출을 허용한다. 부모 카드는 원본 배경에 남고, 자식의 실제 둘레는 기존 단색 검사(2px 전체 고리, 색상 편차/불일치 비율)로 검사한다. 동일 영역·부분 교차·동일 레벨·이미지 부모는 계속 거절한다. 자동 안전 기준의 임계값을 낮추지 않았다.
2. 배경 확인이 없거나 모든 후보가 거절돼도 배경 한 장을 생성해 페이지 적용이 가능했다. 실제 편집 개수는 `provenance.regionId`가 있는 객체만 센다. 0개이면 미리보기에서 제외 이유를 보여주고 적용 버튼과 적용 함수 모두 차단한다. 원본을 성공 결과로 세지 않는다.
3. 복잡한 경계/가장자리는 Python/OpenCV 경로에 의존했다. 기존 경로는 유지하고, 브라우저에서 선택 영역별로 경계·원문·마스크·배경색을 교정할 수 있도록 연결했다. 수동 단색 교체는 색 선택과 별도 확인이 필요하며, 좌표·다각형·색 변경 시 확인/미리보기가 무효화된다. 다른 객체와의 충돌이나 이미지 밖 좌표를 우회하지 않는다. 원본 제거와 새 객체 생성을 한 번에 적용한다.
4. AI 응답의 수동 확인 필드는 제거한다. 모델이 사용자를 대신해 수동 교정에 동의할 수 없다. 수동 단색 교정은 provenance 및 저장되는 진단에 경고를 남긴다.

## 검증한 범위

실제 3종 모두 **원문을 보며 작성한 영역 목록을 분석 API 응답 위치에 주입**했다. 이는 실제 이미지의 편집/복원 통합 테스트이지 Gemini 인식 정확도 또는 실호출 성공 증거가 아니다. 테스트에는 의도적으로 가짜 수동 승인 필드도 주입해 사용자 확인 전에는 0개로 차단되는지 검사한다.

|---|---:|---:|---:|---:|---:|

각 사례에서 확인한 동작:

- 사용자 확인 전 편집 객체 0개와 적용 차단
- 수동 배경 교정 후 실제 텍스트 1개·이미지 1개 생성
- 편집기에서 텍스트 변경 및 이미지 X 좌표 변경을 저장 데이터로 확인
- 이미지 삭제 후 출력 PNG 생성
- 제거한 **사각 영역 전체**가 교정색으로 채워져 기존 픽셀이 남지 않음
- 사각 영역 바깥 모든 픽셀 불변
- 실제 ZIP 다운로드 → 별도 브라우저 컨텍스트에서 가져오기 → 객체·에셋 전체 동일성 확인
- JavaScript pageerror 0개

객체 2개는 전체 원본의 모든 요소가 편집 가능하다는 뜻이 아니다. 나머지 객체는 잠긴 래스터 배경에 남는다. 마스크 없는 이미지는 사각 크롭이며 정확한 의미 분리로 평가하지 않는다.

추가로 카드 포함 관계와 복잡한 배경을 가진 합성 회귀 2종을 검사했다. 기존 preservation 브라우저 회귀는 한글·다각형 이미지·원본 잔상·PNG/PDF/PPTX·ZIP·저장 실패 처리까지 검사한다.

## 시각 품질과 남은 제한

한국어 원본의 제목과 안전모 위치에서 잔상은 제거됐지만 단색 교정 영역의 **이음새가 보인다**. 질감·그림자·그라데이션의 정밀 복원은 실패/미지원으로 남긴다. 복잡한 배경의 단색 대체를 정밀 복원으로 판정하지 않았다. 원본 에셋과 원본 페이지는 보존한다.

- Gemini 실호출: 실행 환경의 `generativelanguage.googleapis.com` 연결이 프록시 `403 Forbidden`으로 차단된다. 키는 출력하거나 변경하지 않았다. 호스트 허용 후 실제 API → 정규화 → 검토 → 복원 → 편집 → ZIP을 다시 검증해야 한다.
- Vercel의 Python/OpenCV 복원 실행과 품질은 이번 검증에 포함하지 않았다. 새로운 수동 경로는 Python·외부 이미지 전송이 필요 없다.
- 자동 마스크의 의미 정확도, 전체 객체 재현율, 전 원본 100% 편집 가능 여부는 검증하지 않았다. 이를 충족하기 전에는 사용자가 요청한 전체 자동 편집 베타 완료로 표시하지 않는다.
