# Personal Magic Studio architecture

Base: onlinecodex/fidelity-v2 `0baf282ef35aff119296852f149964c059165e29`. No fidelity engine, old tests or output files modified.

Inspected Canvix `8aa4cf98bb54d95950d8dc4bd241f6ffbd33b0f8`, especially API route, reconstruct, MagicLayersDialog, provider. Its DB/session/collaboration routes couple the full app to PostgreSQL/Prisma and ZAI. Reuse choice: independent Next.js app in apps/studio with the actual Canvix document factories, immutable editor store (history, page and layer operations), Konva element renderer, image cache and geometry helpers, under MIT. Remove server persistence from the store. No upstream DB, user or chat routes are shipped. This is substantial editor code reuse, not a fresh canvas implementation. Korean shell and storage/import/export adapters are new.

IndexedDB holds versioned project snapshots plus original data URL assets; assets also have dimensions/MIME. ZIP writes JSON and binary assets with hashes; import validates schema, IDs, MIME, sizes and references before opening. Render assets and original pixels remain separate. PNG/PDF rasterize pages; PPTX sends validated local data to a Node route that launches a bounded Python adapter and reuses the unchanged fidelity builder. No filesystem path or network URL accepted from clients. Temporary export directories are removed.

AiAnalyzer: disabled or Gemini (@google/genai server SDK). Explicit image-transmission consent; one server request at a time, quotas, decoded-image validation, model probe, strict structured JSON, no automatic generation retries. Coordinates are [x,y,w,h] in 0..1000, polygon [x,y] in the same space. No inferred confidence scores. User corrections can use region boxes or polygons offline. Backgrounds are reconstructed deterministically only when the user confirms solid/gradient approximation; photo backgrounds retain an explicit correction warning. No image generation, GPU provisioning or silent paid fallback.

Magic reconstruction fits the source inside the shared page canvas with uniform scaling and centered padding; original and reconstructed objects retain aspect ratio even when page/source dimensions differ. Mask crops copy an integer ROI one-to-one with transparent padding and record original ROI pixels. The PPTX adapter certifies eligible source masks using unchanged fidelity.validate_masked (SHA, alpha, opaque pixels, residual). It retains user-approved provenance when certification fails and never sets full-page image-fidelity QA flags to true automatically.


Phase 2 preservation checkpoint: Google wire coordinates `[ymin,xmin,ymax,xmax]` are normalized to Studio XYWH and explicit bbox-local/whole-image polygons before reconstruction. Candidate catalog and fail-closed billing policy are server-side inputs. Default API is Interactions with `store:false`, `maxRetries:0`, low thinking; explicit legacy generate-content remains available. Separate mask analysis is an API-only option (max two generation calls, no retries). Live account acceptance is unverified.

`POST /api/ai/connection` probes metadata only. `POST /api/magic-layers/background` calls a CPU OpenCV Telea/NS helper over stdin, reusing px-image2pptx text masks. It returns repaired background, text-erased object source and masks, preserving unmasked pixels. **UI/reconstruct integration is pending.** Existing reconstruct.ts and the fidelity engine are unchanged. PNG mask schema support does not yet mean browser PNG alpha-mask decoding is implemented.
