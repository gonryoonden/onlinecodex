# Codex Cloud Master Task — Personal Magic Studio

작성 기준일: 2026-10-30
작업 유형: 설계 문서 작성이 아닌 **실제 동작하는 제품 구현·검증·인계**
사용 대상: 개인 사용자 1명. 한국어 중심 인포그래픽·포스터·안내문·프레젠테이션 이미지.

## 0. 임무와 행동 원칙

당신은 단순 코드 작성자가 아니라, 테크리드·풀스택 개발자·이미지 처리 엔지니어·QA·DevOps 역할을 수행하는 구현 에이전트다. 이 메시지를 받고 계획만 작성하거나 기술 조사로 끝내지 말고, **현재 Codex Cloud에 연결된 GitHub 작업 공간에서 코드를 수정하고 실제로 실행·테스트·수정하라.** 작업의 목표는 개인이 웹브라우저에서 실제 활용할 수 있는 Canva형 편집기, 특히 이미지 한 장을 편집 레이어로 재구성하는 기능을 완성하는 것이다.

우선순위: (1) 실행 가능성·데이터 보존 (2) 일반 웹 편집기 완성 (3) 정직하고 검증된 이미지 레이어 재구성 (4) 내보내기 (5) 개인용 보호 배포. 멋진 시연 영상, 목업, 문서만으로 성공 처리하지 말라.

작업 중 기존 사용자 프로젝트 파일, Git 이력, output 및 fidelity 엔진을 삭제·강제 덮어쓰기하지 않는다. 라이선스와 출처를 보존한다. 사용자 API 키·DB 비밀번호 등은 코드·커밋·로그에 기록하지 않는다. 비밀 값, 도메인 소유권, 계정 연결 등 사용자가 제공해야 하는 권한만 구체적 블로커로 명시한다. 그 외에는 스스로 선택·구현·검증하며 진행한다. 사용자에게 사소한 선택을 반복해서 묻지 말라.

**완료의 정의:** `README`의 절차로 새 환경에서 앱이 실행되고, 이미지 업로드→편집 또는 AI 분해→텍스트/레이어 수정→저장→재접속 후 다시 편집→PNG·PDF·PPTX 출력이 실제 테스트로 입증되는 것. AI 키가 없을 때는 기본 편집기 및 파일 기능이 반드시 작동하고, AI 기능만 명확히 비활성화되어야 한다. 외부 자격 증명이 없어서 라이브 API/실배포를 검증하지 못한 경우에는 해당 항목을 `BLOCKED`로 표시하고 완전한 성공을 주장하지 말라.

## 2. 제품 요구사항: 개인용 Canva형 웹 에디터

### A. 비 AI 기능 — 필수

1. 브라우저에서 열리는 기본 한국어 UI: 프로젝트 목록/새 디자인, 캔버스, 왼쪽 도구 패널, 오른쪽 레이어 패널, 상단 저장/내보내기.
2. PNG/JPEG/WebP 이미지 업로드·배치; PDF는 페이지별 이미지를 추출하여 다중 페이지로 불러오기(원본 PDF가 자동으로 네이티브 편집 객체가 되는 것은 아님을 알림). 가로세로 비율 유지, 원본 해상도/원본 픽셀을 보존하는 프로젝트 에셋 관리. 향후 PPTX 가져오기를 지원할 수 있도록 import 인터페이스 분리.
3. 네이티브 편집 객체: 한글 텍스트(직접 글자 수정, 글꼴·크기·색·정렬·줄바꿈), 도형(사각형/모서리 둥근 사각형/원/선), 이미지 레이어(이동/회전/확대축소/삭제/복제/투명도), 배경색/그라데이션.
4. 레이어 순서 변경/표시·숨김/잠금/이름 변경, 다중 선택 및 정렬, 캔버스 확대/축소, 되돌리기/다시 실행(Ctrl+Z/Shift+Ctrl+Z).
5. 최소 2페이지 이상 관리(추가/복제/순서 변경), 서로 다른 페이지의 개체가 섞이지 않아야 한다.
6. 자동저장과 수동저장, 브라우저 재시작·새로고침 이후 다시 열기. 로그인·DB·AI 키 없이도 실행할 수 있는 `local-first` 모드(IndexedDB 등)를 우선 제공한다. 외부 DB가 필요한 기존 코드라면 개인용 무DB 모드 또는 로컬 DB 대안을 구현·문서화하고 셋업을 복잡하게 만들지 말 것.
7. 프로젝트 전체를 재편집할 수 있게 구조화된 JSON+이미지 에셋 ZIP 등으로 내보내고 다시 불러오기. 저장 데이터의 파일 포맷/스키마 버전을 정의하고 누락된 에셋 오류를 표시한다.
8. PNG, PDF 내보내기. PPTX도 필수(아래 섹션 4); 원본을 단순한 하나의 그림으로 슬라이드에 붙인 '가짜 편집 가능 PPTX'는 금지.
9. 모바일 전체 최적화는 필수 아님; 데스크톱 Chrome에서 조작 가능하고 1366x768에서 주요 기능이 가려지지 않아야 한다.

### B. Magic Layers — 필수이며 일반 편집기와 별도 기능

사용자 흐름: 이미지 업로드 → `AI 레이어 분해` → 분석 진행/오류 상태 → 인식된 텍스트/도형/이미지 목록 및 미리보기 → 사용자가 개별 영역 채택·제외 또는 영역 수정 → 편집 가능한 레이어로 생성 → 이동/삭제/글자 수정 → 결과 저장·출력.

1. 이미지 전체를 단일 배경 PNG로 두고 위에 텍스트만 얹는 트릭은 금지. 원본에 글자가 남아있어 텍스트 이동 시 복제·잔상이 생기면 해당 결과를 정확히 분리된 것으로 표시하지 말 것.
2. 텍스트: 한국어 OCR/비전 인식 결과를 실제 `text` 객체로 생성하고, 이미지 좌표와 글꼴 크기·색상·정렬을 가능한 범위에서 복원한다. 정확히 판독할 수 없는 글자는 `확인 필요`로 표시하고 원문과 나란히 비교·수정하게 한다. Noto Sans CJK 또는 사용 가능한 한글 폰트를 적용해 자소 깨짐 없이 표시한다.
3. 단순 도형: 사각형·원·라인은 가능하면 native shape로 생성한다. 복잡한 장식은 무리하게 벡터로 변환하지 말고 이미지 레이어로 명확히 구분한다.
4. 시각 객체: 경계상자만이 아닌 polygon/segmentation mask를 처리할 수 있는 경로를 설계한다. 원본 이미지 픽셀을 알파 마스크로 잘라 투명 PNG를 생성하고, 이동·크기 변경 시 원본 이미지에 포함된 사각형 배경이 함께 따라다니지 않는지 검증한다. 마스크가 없을 경우 사각형 크롭을 할 수는 있으나 `근사 크롭` 배지를 표시하고 정확한 레이어로 속이지 않는다.
5. 객체가 사라진 배경을 복원해야 한다. 간단한 단색·그라데이션 배경은 결정론적 배경 복원; 복잡한 배경은 선택적인 로컬 inpainting/오픈소스 방식 또는 사용자가 명시적으로 허용한 이미지 API를 사용한다. 배경 복원 실패는 감추지 않고, 미리보기에서 잔상이 있으면 `배경 보정 필요`로 표시한다. 완벽한 원본 복원 보장 금지.
6. 사용자가 마스크를 직접 추가/제거·브러시/다각형 편집할 수 있게 하거나 최소한 영역 재선택/재분석 기능을 제공한다. 불확실성/신뢰도(모델 confidence가 의미 있는 경우에만)와 실제 출처를 기록한다.
7. `원본과 변환 결과 비교` 보기: 좌우 또는 오버레이, 확대 비교; 텍스트 누락·잘린 객체를 발견할 수 있어야 한다.
8. AI 없이도 일반 편집기 완전 동작. AI 키가 없으면 `연결 필요`를 표시하고 분석 성공을 모의로 위장하지 말라. 개발용 `mock fixture`는 테스트 모드로만 명시할 것.

## 3. Gemini API 연동: 비용·정확도·보안

- 공식 Google `@google/genai` 서버 SDK 우선. 기존 Canvix의 ZAI 분석 경로를 분리된 `AiAnalyzer` 인터페이스 및 Gemini 구현체로 교체하되, 무키 `disabled` 어댑터를 유지한다. 클라이언트에 `GEMINI_API_KEY` 노출 금지.
- 환경 변수: `GEMINI_API_KEY`, `GEMINI_VISION_MODEL` (기본 후보는 무료 티어에서 이용 가능한 `gemini-2.5-flash`, 실제 계정과 문서에서 가용성을 런타임 점검), `ENABLE_PAID_AI=false` 기본값. 자동으로 유료 이미지 생성 모델 호출 금지. UI에서 API 예상 호출·실패·할당량 초과를 사용자에게 안내.
- Gemini의 image understanding/documented structured JSON, 객체 경계상자, 다각형 mask 결과를 이용한다. 기능·모델 가용성은 **반드시 실측/공식 문서로 검사**한다. 다른 Gemini 모델에서 segmentation 지원을 가정하지 말고, 마스크 미지원이면 바운딩 박스+근사 크롭 또는 추가 로컬 마스크 처리를 명시한다. 모델 실패·429·타임아웃 시 잘못된 JSON을 저장하지 말고 검증·재시도(최대 2회)·진단을 제공한다.
- Zod/JSON Schema로 `id`, `type`, `text`, `bbox`, `polygon mask`, `style`, `zIndex`, `sourcePixels`, `confidence` 등을 검증하고 0..1000↔원본 픽셀 좌표 변환을 단위 테스트한다. 여러 좌표 형식(x/y, y/x)을 혼동하지 말라. 모델이 임의로 없는 내용을 생성하면 실패로 취급한다.
- 업로드 이미지 전체를 무조건 외부 서비스에 전송하지 않는다. 분석 버튼에서 '외부 Gemini API로 이미지 전송' 동의를 명확히 표시한다. API 없는 작업은 로컬 처리. 개인정보·업무 기밀 이미지는 무료 티어로 전송하면 안 될 수 있음을 UI에 알린다.
- 개인용 기본 호출량 제한·동시요청 제한·파일 크기 및 픽셀 제한·서버 입력 검증·에러 처리. API 비용을 임의로 추정해 확정 금액이라 주장하지 말 것.

## 4. 기존 onlinecodex/editppt를 활용한 PPTX 내보내기

- `fidelity-v2`에 있는 `editppt` manifest 형식과 builder/validation, 기존 tests를 실제 확인한다. `text_boxes`, `shapes`, `images`, `box_px`, `points_px`, z_index, provenance 규칙을 준수하는 **Studio→Manifest 어댑터**를 구현한다.
- 저장된 레이어를 네이티브 PowerPoint 텍스트·도형·이미지 객체로 반영한다. PNG로 평탄화한 후 PPTX에 한 장으로 삽입하는 방식 금지(단, SVG/일러스트 자체가 래스터인 객체는 이미지 객체로 포함 가능).
- 한 페이지, 두 페이지 이상 PPTX 생성·열기·검증을 테스트한다. 이미지 에셋 경로가 재시작·배포 환경에서도 안정적으로 해석되어야 한다. Python 서비스가 필요하면 명확히 분리하고 로컬 시작 명령/필요 패키지를 문서화한다.
- PPTX 변환 엔진 전체를 새로 쓰지 말고 필요한 어댑터만 개발한다. 문서 구조를 보존하면서 가능하면 향후 PPTX 가져오기 기능도 확장할 수 있도록 인터페이스 분리.

## 5. 아키텍처·성능·개인용 배포

- 가능한 한 Next.js + React + Konva + TypeScript를 유지한다. AI는 서버 측 route, 파일 및 프로젝트 데이터는 로컬 우선. 복잡한 이미지 처리나 PPTX 출력에 필요한 Python 부분만 별도 로컬 API/작업 프로세스로 분리한다.
- 개인 사용자에게 불필요한 협업/채팅/광고/결제/회원관리 기능을 우선 구현하지 말라. 핵심 흐름을 깨지 않고 제거·비활성화할 수 있으면 단순화. 새로운 거대 프레임워크 도입 금지.
- 로컬 실행: Windows 사용자를 위한 명령(PowerShell/WSL 또는 Docker 중 실제 검증 가능한 경로)과 Linux Codex 환경 시작 명령 제공. `./scripts/dev` 또는 `npm run dev` 등 최소 명령으로 실행 가능. .env.example 제공. 공개 비밀 값 없음.
- 배포: 호스팅 환경 접근 권한이 이미 준비되어 있고 HTTPS/인증/비밀키 안전성이 검증된 경우에만 개인용 접근 통제된 배포를 진행한다. 그렇지 않으면 **공개 인터넷에 무인증 앱을 배포하지 말고**, 재현 가능한 Vercel 등 배포 절차와 미완료 권한 요구를 명시한다. Vercel 정적/서버리스에서 실행 불가능한 무거운 Python 이미지 처리·GPU 기능은 외부 작업 서버로 분리하거나 로컬 전용임을 밝힐 것. 불필요한 GPU 인스턴스·유료 서비스 생성 금지.
- 이미지 업로드에서 MIME/용량 검증, path traversal·SSRF·XSS 보호, 내부 데이터 접근 제어, secret 무노출. 종속성 보안 체크 후 중대한 취약점은 가능한 범위에서 수정.
- 새로고침·화면 이동·오류로 인해 사용자의 편집 데이터가 사라지지 않아야 한다. Autosave 실패 상태/수동 백업을 제공한다.

## 6. 자동 검증과 수락 기준 (모두 수행)

### 필수 픽스처

- 기존 저장소의 `2024년_산업안전보건교육_주요_개정_요약.png`가 존재하면 실제 변환 시험에 사용. 한글·복합 레이어가 많은 **현실 검증용**이며, 품질이 부족하면 정확히 기록할 것.
- 테스트용으로 생성한 단색 배경+한글 문구+원/사각형 3개 이상+겹치는 객체 1개 이미지를 **정답이 알려진 synthetic fixture**로 추가. 모델 비사용 버전의 레이어 조작·배경·좌표·텍스트 검증용.
- 반드시 인터넷/API 키가 없어도 수행할 수 있는 유닛/통합/E2E 테스트를 포함하고, 라이브 Gemini E2E는 키가 제공된 경우에만 별도로 실행한다.

### 통과 테스트

- [ ] 빈 저장소 환경 또는 문서화된 배포 환경에서 의존성 설치 후 앱 실행. `npm run typecheck`, lint, unit test, production build 통과.
- [ ] Chrome 또는 Playwright 브라우저 테스트에서 화면 표시와 파일 업로드 성공; 콘솔 오류/클라이언트 크래시 없음.
- [ ] 새 프로젝트에 한글 텍스트/도형/이미지 추가→텍스트 수정·이동·숨김/잠금·레이어 순서·되돌리기→저장→새로고침→동일 데이터 복원.
- [ ] 원본 이미지를 평탄화된 객체와 분리하여 관리, 결과물을 확대·이동해도 좌표 및 이미지 비율 정상.
- [ ] synthetic fixture에서 native text는 실제 글자 수정 가능, native shape는 실제 도형 편집 가능; 실제 분리된 객체의 외부 영역은 알파 투명. 텍스트/객체를 이동할 때 원본 위치의 눈에 띄는 잔상이 남지 않거나 `배경 보정 필요` 경고가 보임. 무조건 성공으로 처리 금지.
- [ ] API 키 없는 상황의 `AI 비활성` 메시지와 일반 편집 작업 정상; 가짜 AI 결과로 성공하는 코드는 테스트 전용 mock 외에 없음.
- [ ] 유효하지 않은 segmentation polygon/잘못된 JSON/미지원 모델/429/타임아웃 처리 오류 메시지 및 프로젝트 무손상.
- [ ] 프로젝트 파일 내보내기→새 세션에서 가져오기 후 동일 레이어 개수·텍스트·순서·이미지 에셋 복원.
- [ ] PNG·PDF 파일 실제 생성 후 열람 가능; PPTX 파일 실제 생성, 압축/미디어 무결성·슬라이드 개수·네이티브 텍스트 및 도형 존재 확인. 원본 raster 한 장만 포함하면 실패.
- [ ] 2페이지 문서의 순서/서로 다른 개체가 출력에 반영됨.
- [ ] `fidelity-v2` 기존 테스트 실행 및 회귀가 없는지 기록. 실패 시 기존 실패/신규 실패 구분.
- [ ] 변경된 UI의 자동 스크린샷 및 원본-변환 비교 이미지/리포트 생성. 스크린샷 실행할 도구가 없으면 그 사실을 증거와 함께 명시하고 재현 명령 제공. 성공한 척하지 말 것.
- [ ] API 키·DB 비밀번호·개인 데이터 Git 커밋에 포함되지 않았음; 오픈소스 저작권/라이선스 보존.

테스트 명령은 실제 선택한 프로젝트 package scripts와 Python 환경에 맞게 수정해 문서에 기록하되, 테스트를 생략한 채 통과한 것처럼 표기하지 않는다. Magic Layers의 범용 100% 정확도는 현실적으로 보장하지 않는다. 원본/합성 픽스처별 성공·근사·실패를 분류한다.

## 7. 수행 순서 — 계획 보고 후 반드시 구현

0. 리포지토리 상태/브랜치/라이선스/관련 도구 조사 → 아키텍처 결정(`docs/architecture.md`); 조사로 종료하지 말 것.
1. 독립 브랜치와 앱 셸 마련, Canvix 편집 기능 재사용, 의존성 설치, 첫 로컬 실행 및 확인.
2. 로컬 우선 프로젝트 저장·가져오기·일반 편집·PNG/PDF 작동 및 E2E 검증.
3. Magic Layers 구조·Gemini 제공자·검증 스키마·AI 미설정 폴백 구현.
4. 실제 객체 알파 분리·한글 텍스트/도형 복원·배경 정리·사용자 보정·원본 비교 구현.
5. `editppt` PPTX 어댑터 연결 및 단일/다중 페이지 검증.
6. 모든 테스트/시각 QA 반복 수행하여 장애 수정, README·사용설명서·품질 제한 문서 완성.
7. 가능한 경우에만 안전한 개인용 배포/PR 작성, 불가능하면 재현 가능한 배포 스크립트와 필요한 자격 증명 목록 문서화.

각 단계가 실패하면 관련 로그를 읽고 수정한 뒤 **다시 검증**한다. 같은 명령을 조건 변경 없이 무한 반복하지 않는다. 외부 서비스 키 없이도 만들 수 있는 기능부터 끝낸다. 우선순위 높은 필수 기능을 하지 않은 채 선택 기능·미관 작업으로 시간을 소비하지 말라.

## 8. 최종 산출물 및 보고 형식

실제 Git 커밋과 변경 파일을 남겨라. 접근 가능한 경우 GitHub PR 생성. 마지막 메시지에 다음 정보를 반드시 포함한다.

1. 한 줄 제품 상태: `완료 / 부분 완료 / 블로커` 중 하나만 선택. 완성 기준 미달이면 `완료` 금지.
2. 작업 브랜치·커밋 SHA·PR URL(존재할 경우).
3. 실행 URL(실제 접속·인증을 검증한 경우) 또는 로컬 실행 명령. 가상 URL 금지.
4. 실제 구현 기능/미구현 기능을 각각 정확히 설명.
5. 수락 테스트 13항목 PASS/FAIL/BLOCKED 표 + 실제 실행 명령/결과/스크린샷 및 PPTX 검사 결과.
6. 사용자에게 꼭 필요한 후속 조치(예: `GEMINI_API_KEY` 환경변수 등록, 클라우드 서비스 접근 권한)만 표시. 비밀 키를 채팅에 붙여넣도록 요구 금지.
7. `docs/architecture.md`, `README.md`, `.env.example`, `THIRD_PARTY_NOTICES.md`, `docs/limitations.md`, `tests/` 및 샘플 파일·시연 증거의 위치.
8. 무료로 실행 가능한 부분과 유료/쿼터 의존 기능을 구별하고, 무료 티어 계정의 API 한계·민감 자료 외부 전송 주의사항 명시.

**다시 강조:** 이 작업은 계획 요청이 아니라 구현 요청이다. 동작하지 않는 버튼, mock 결과를 실제 AI처럼 표시하는 시연, 단일 이미지 평탄화 PPTX, 사용자의 키가 없다는 이유로 전체 작업을 중단하는 행동을 허용하지 않는다. 환경적으로 불가능한 부분을 숨기지 말고, 나머지 기능을 검증 가능한 완성 상태까지 진행하라.
